## Featured Projects

### 🤖 JARVIS — Local-First Personal AI Assistant

> A local-first personal AI assistant combining LLM inference, voice interaction, memory, automation, and a custom interface into a practical desktop AI companion — built to be used daily, not demoed once.

**Why it exists:** Most "AI assistant" demos are thin wrappers around a hosted API. JARVIS runs inference locally (via Ollama + Qwen 2.5 7B), keeps its own memory, and is designed as infrastructure I actually rely on, not a portfolio piece.

`Python` `Flask` `Ollama` `Qwen 2.5 7B` `Local Inference` `Voice I/O` `Memory System` `Automation`

[GitHub Repository](YOUR_REPOSITORY_URL)

<br/>

### 📊 XAUUSD Replay — Trading Replay & Analysis Platform

> A market replay and analysis application for practicing and studying trading decisions on historical XAUUSD price action — built in the spirit of tools like FX Replay, from scratch.

**Why it exists:** Backtesting on static charts hides how a strategy actually feels to trade in real time. This platform replays historical price bar-by-bar so strategy execution and decision-making can be practiced honestly.

`Python` `Chart/Replay Engine` `Backtesting` `Historical Market Data` `Trading Tooling`

[**GitHub Repository →**](https://github.com/imrans4569k-droid/xauusd-replay)

<br/>

### 🛰️ LOOP — Web Recon & Security Research Platform

> An authenticated, evidence-backed web crawler and scanning platform that discovers assets, renders JavaScript, captures screenshots, and produces structured findings and reports rather than a noisy scan log.

**Why it exists:** Most recon tooling gives you a flood of unverified findings. LOOP is built around a crawler → detector → finding → evidence pipeline, so every result is traceable back to concrete evidence, with trend comparison across scans.

`Python` `Crawler/Detector Architecture` `SQLite` `Screenshot & Evidence Capture` `JS Rendering` `Reporting`

[GitHub Repository](YOUR_REPOSITORY_URL)

<br/>

### 📡 Smart Scan Strategy for Electronic Warfare — SIH26055

> A simulation-driven prototype exploring resource allocation strategies for an Electronic Support Measures (ESM) receiver, comparing Round Robin, priority-based heuristics, UCB bandit approaches, and sliding-window/discounted methods for non-stationary environments.

**Why it exists:** Built as a Smart India Hackathon problem-statement prototype focused on decision-making under uncertainty — treating scan scheduling as a resource-allocation and optimization problem rather than a fixed rule set.

`Python` `Simulation` `Multi-Armed Bandits (UCB)` `Optimization` `Decision Systems`

[GitHub Repository](YOUR_REPOSITORY_URL)
